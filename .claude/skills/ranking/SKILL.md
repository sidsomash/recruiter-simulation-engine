# Ranking Skill
This skill loads all simulation outputs generated by the simulation skill,
extracts structured evaluation data, computes a weighted composite score for
each role, and produces a ranked table of best-fit positions.

The ranking skill does not generate simulations — it only consumes them.

---

## 📁 Simulation Source Directory

This skill reads all simulation outputs from: `skills/simulation/simulations/`.

Each file must be a completed simulation output generated by the simulation skill.

---

## 📚 Dependencies

This skill depends on the scoring policy defined in:

- `references/ranking_rules.md`

This file contains the **canonical scoring model**, including:
- weighted factors  
- penalties  
- tie-breakers  
- internship handling  
- fit category scoring  

The ranking skill must not redefine or override these rules.

Additionally, this skill depends on the output formatting template defined in:

- `assets/templates/ranking_output_template.md`

This template defines the required structure for the ranked output table, including column order, summary sections, and formatting conventions.

The ranking skill must follow this template when generating output.

---

## 📝 Inputs

This skill accepts **no inputs**.

It automatically discovers and ranks all simulation files in the simulations directory.

---

## 🧠 Scoring Model

The ranking skill uses the scoring model defined in: `references/ranking_rules.md`

This includes:

- recruiter screen likelihood weighting  
- interview likelihood weighting  
- degree alignment scoring  
- skill alignment scoring  
- experience alignment scoring  
- preference violation penalties  
- final fit summary scoring  
- composite score formula  
- tie-breaker rules  
- internship separation rules  

The SKILL.md does not restate these rules to avoid duplication and drift.

---

## 🧩 Data Extraction

From each simulation output, the ranking skill extracts:

- Role Title  
- Company / Employer  
- Recruiter Screen Likelihood  
- Interview Likelihood  
- Compensation / Pay Range (if present)  
- Location(s)  
- Degree Alignment Score  
- Skill Alignment Score  
- Experience Alignment Score  
- Years-of-Experience Required (parsed)  
- Preference Violations  
- Final Fit Summary Category  
- Internship Mode Flag  
- Posting Date / Source URL (if present)  

The ranking skill must prefer explicit metadata extracted by the simulation (Metadata section) over filename heuristics; when metadata fields are missing, fall back to conservative inference. These fields are required for scoring.

---

## 🧮 Workflow

### **Step 1 — Load All Simulation Files**
Read all `.md` files in: `skills/simulation/simulations/`

If no files exist, return an error.

---

### **Step 2 — Parse Each Simulation Output**
Extract structured fields using the known simulation output template.

---

### **Step 3 — Apply Scoring Model**
Compute all scoring dimensions and the composite score using the rules in: `references/ranking_rules.md`

---

### **Step 4 — Sort Simulations**
Sort descending by composite score, applying tie-breakers as defined in the rules.

If internship mode is detected:
- produce separate rankings for internships and full-time roles.

---

### **Step 5 — Generate Ranked Table Output**

The output table includes:

| Rank | Role | Score | Recruiter Screen | Interview | Degree | Skills | Experience | Pref Penalties | Fit Summary |
|------|------|--------|------------------|-----------|--------|--------|------------|----------------|-------------|

---

### **Step 6 — Return Output**

Persist the complete ranking as a CSV at: `assets/ranking_results.csv`. Behavior:

- The ranking skill MUST write a CSV file to `assets/ranking_results.csv` on each invocation and OVERWRITE any existing file with the new ranked results.
- The CSV file format and column ordering are defined in `assets/templates/ranking_output_template.md` and must be followed exactly.
- Do NOT print the full table to stdout. Instead, after writing the CSV, the skill MUST emit a short confirmation message indicating the CSV was updated (e.g., "Ranking persisted to assets/ranking_results.csv").

Persisting the CSV enables downstream programmatic consumption; the ranking skill must still follow the canonical scoring model in `references/ranking_rules.md`.

---

## ⚠️ Error Handling

- If the simulations directory is empty → return a clear message.  
- If a simulation file is malformed → skip it and warn the user.  
- If required sections are missing → treat missing fields as neutral (0.5).  
- If scoring fails → return a structured error.

---

## 🧾 Notes

- This skill does not modify or generate simulation files.  
- This skill is deterministic: same inputs → same ranking.  
- The scoring model lives exclusively in `ranking_rules.md`.  
- The SKILL.md must not redefine scoring logic.
