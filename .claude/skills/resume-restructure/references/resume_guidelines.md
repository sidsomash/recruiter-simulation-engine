# Resume Rewrite Guidelines v1.0
### (Generalized, Candidate‑Agnostic, ATS‑Optimized)

## 1. Purpose
These guidelines define how the resume‑restructure skill rewrites a candidate’s résumé
to align with a target job description (JD) while preserving factual accuracy.

The rewritten résumé must:
- Highlight the most relevant skills and experience for the JD  
- Improve clarity, impact, and recruiter readability  
- Maintain strict truthfulness  
- Preserve the candidate’s authentic background  
- Follow ATS‑friendly formatting  

The goal is **alignment**, not fabrication.

---

## 2. Core Principles

### 2.1 Truthfulness
- No fabricated experience, skills, or achievements  
- No inflated titles or responsibilities  
- No invented metrics  
- Allowed: reframing, reorganizing, quantifying existing work  

### 2.2 Relevance
- Prioritize content that aligns with the JD  
- De‑emphasize unrelated experience  
- Remove filler, fluff, and generic statements  

### 2.3 Clarity
- Use concise, high‑impact bullet points  
- Lead with action verbs  
- Quantify impact wherever possible  
- Avoid jargon unless industry‑standard  

### 2.4 ATS Compatibility
- No tables, text boxes, or multi‑column layouts  
- Use standard section headers  
- Use consistent date formats  
- Spell out acronyms on first use  

---

## 3. Required Resume Sections

A rewritten résumé must include:

1. **Header**  
   - Name, email, phone, location (city/state), LinkedIn (optional)

2. **Skills Section**  
   - Grouped by category (Languages, Tools, Cloud, Frameworks, etc.)  
   - Prioritized based on JD relevance  

3. **Experience Section**  
   - Reverse chronological  
   - Each role includes:
     - Company  
     - Title  
     - Location  
     - Dates  
     - 3–5 bullets rewritten for JD alignment  

4. **Projects Section** (optional but recommended)  
   - Only include projects relevant to the JD  
   - 2–3 bullets per project  

5. **Education Section**  
   - Degree, major, institution, graduation date  
   - Certifications (optional)  

---

## 4. Bullet Point Rewrite Rules

### 4.1 Structure
Each bullet must follow:

Action verb → What you did → How you did it → Impact (quantified if possible)

### 4.2 Action Verbs
Use strong verbs:
- Built, engineered, developed, designed  
- Automated, optimized, deployed  
- Analyzed, modeled, evaluated  
- Architected, orchestrated, implemented  

Avoid weak verbs:
- Helped, assisted, worked on, responsible for  

### 4.3 Quantification
Where possible, include:
- percentages  
- time saved  
- throughput improvements  
- scale (dataset size, user count, etc.)  

### 4.4 JD Alignment
Rewrite bullets to emphasize:
- required skills  
- preferred skills  
- responsibilities listed in the JD  

Do **not**:
- copy JD language verbatim  
- misrepresent experience  

---

## 5. Skills Section Rewrite Rules

### 5.1 Prioritization
Skills must be reordered so that:
- JD‑required skills appear first  
- JD‑preferred skills appear next  
- Irrelevant skills are moved to the bottom or removed  

### 5.2 Normalization
Normalize skill names:
- “PySpark” → “Spark (PySpark)”  
- “Postgres” → “PostgreSQL”  
- “LLM” → “Large Language Models (LLMs)”  

### 5.3 No Skill Inflation
Do not add skills the candidate does not have.

---

## 6. Experience Rewrite Rules

### 6.1 Relevance Weighting
For each role:
- Keep 3–5 bullets  
- Rewrite bullets to emphasize JD‑aligned responsibilities  
- Remove or downplay unrelated tasks  

### 6.2 Technical Depth
If the JD is technical:
- Increase specificity (tools, frameworks, cloud platforms)  
- Highlight architecture, pipelines, systems, and scale  

If the JD is less technical:
- Emphasize business impact, collaboration, communication  

### 6.3 Seniority Alignment
If the JD is:
- **Entry‑level** → emphasize projects, internships, coursework  
- **Mid‑level** → emphasize ownership, autonomy, impact  
- **Senior** → emphasize leadership, architecture, cross‑team influence  

---

## 7. Project Rewrite Rules

### 7.1 Relevance
Only include projects that:
- Demonstrate JD‑aligned skills  
- Show technical depth or problem‑solving  

### 7.2 Structure
Each project must include:
- One‑line summary  
- 2–3 bullets describing:
  - tools used  
  - architecture or approach  
  - measurable outcomes  

---

## 8. Formatting Rules

### 8.1 Layout
- Single column  
- One page (preferred)  
- Two pages only for 8+ years experience  

### 8.2 Typography
- Standard fonts (Arial, Calibri, Helvetica, Times)  
- 10–12 pt body text  
- Bold for section headers and company names  

### 8.3 Dates
Use consistent format:
- “May 2025 – Present”  
- “Jun 2024 – Aug 2024”  

### 8.4 File Format
- Plain text or Markdown for internal processing  
- PDF for final export (outside the skill)  

---

## 9. Prohibited Content
The rewritten résumé must not include:
- Fabricated achievements  
- Exaggerated titles  
- Personal details (age, marital status, photo)  
- Irrelevant hobbies  
- Buzzwords without substance  

---

## 10. Output Requirements

The resume‑restructure skill must output:

1. **Rewritten Resume**  
   Fully rewritten résumé aligned to the JD.

2. **Change Summary**  
   A list of:
   - Added emphasis areas  
   - Removed content  
   - Rewritten bullets  
   - Skills reordering  

3. **JD Alignment Notes**  
   A short explanation of:
   - Why certain changes were made  
   - How the résumé now aligns with the JD
